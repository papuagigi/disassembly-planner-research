# Claude Code에 붙여 넣을 재개 프롬프트

아래 문장은 실제로 Claude Code에 작업을 넘길 때 사용한다. 이 파일 생성 자체는 위임이 아니다.

---

이 컴퓨터에서 진행 중인 disassembly planner 연구를 이어받아 끝까지 마무리해줘.

작업 폴더는 `/Users/juyeonkim/Documents/경희대학교 26-2학기 관련 문서/독립심화학습`이고, 현재 실험은 `disassembly_final_v6`야. 먼저 그 안의 `CLAUDE.md`, `AGENT_HANDOFF.md`, `OPERATIONS.md`와 최신 실행 상태를 읽어줘. GitHub 복제본에는 재개에 필요한 전체 CAD·가상환경·로그가 없으므로 기존 로컬 폴더를 사용해.

가장 먼저 supervisor와 planner가 실제로 실행 중인지 확인해. 살아 있으면 새로 실행하지 말고 기존 작업을 계속 관찰해. 멈췄다면 오류와 기록을 보존하고 원인을 해결한 뒤 남은 단계만 재개해. 이미 시작한 첫 평가를 삭제하거나 다시 시도하면 안 돼. 학습과 검증은 완료됐으므로 다시 하지 마.

최종 범위는 사용자가 확정한 **새 CAD 3개 × A·B·C = 총 9회 첫 실행**이야. A는 LLM 코드 생성·library 없음, B는 LLM 코드 생성·SKILL.md 있음, C는 Graph·LLM 순위·DFS·같은 SKILL.md야. B·C의 고정 문서는 동일하게 유지해. 새 skill 후보는 검증에서 기각됐고 기존 문서 2개를 사용한다는 점도 기록해.

세 조건 모두 기존 **gpt-6-luna low,4GiB,LLM8회,물리 검사240회,15분 상한과 같은 복원 API**를 유지하고 planner를 하나씩 실행해. Claude는 연구 작업을 관리하는 역할이야. 평가용 LLM을 Claude로 바꾸지 마. Codex 모델 호출까지 막히면 그 원인을 분리하고 미실행 평가를 임의로 대체하지 마.

원래4개 목표와 후보75개 검사 기록,3개로 줄인 사전 변경 기록을 보존해. MuJoCo 자원 부족,LLM 호출 오류,분해 판단 실패,예산 종료를 구분하고 실패·누락 토큰을 숨기지 마. 테스트 결과로 skill이나 planner를 다시 개선하지 마.

남은 평가→결과·토큰 집계→모든 실행의 MuJoCo 재검증·다시보기→동일 조건·기존 결과 보존 확인→GitHub와 agent용 MD 갱신까지 완료해줘. GitHub는 `https://github.com/papuagigi/disassembly-planner-research`이고, 기존 게시 도구를 사용해. 자격증명이나 원본 대형 CAD 묶음은 올리지 마. **PPT는 아직 만들지 마.**

완료됐다고 말하기 전에 실제9개 결과,다시보기 감사 결과,조건 감사,토큰 사용량과 GitHub 반영을 확인해. 결과는 어느 조건이 이기든 그대로 설명해줘. 기존 자동 실행이 살아 있으면 중복 작업을 만드는 대신 그 작업을 끝까지 이어가 줘.
