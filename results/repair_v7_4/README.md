# v7.4 공개 스냅샷

2026-10-21에 완료된 기존 실행 기록을 2026-11-10에 공개했습니다. Planner는 v7.3과 같고, 평가 데이터와 반복 횟수가 달라졌습니다.

2026-11-18 갱신: 사용자 지시로 전체 180회의 독립 재생 검증을 실행했고(180/180 PASS), 집계를 다시 실행했으며, 평가 보고서를 추가했습니다. 두 공개 과정 모두 새 모델 호출이나 새 분해 에피소드를 실행하지 않았습니다.

## 결과와 범위

- 처음 보는 부품 5·6·7개짜리 CAD 각 4종, 총 12종을 평가했습니다. 각 조건을 같은 CAD에서 3회 반복했습니다.
- 1차 A, B(S5), C(S5), 2차 B(S5 + 조립체별 SKILL.md), C(S5 + 조립체별 SKILL.md)가 각각 36/36, 총 180/180회 목표에 도달했습니다. 목표는 고정 부품 하나를 제외한 나머지 부품의 안정적인 제거입니다.
- 범용 SKILL.md S5는 v7.3 개발 검증에서 불승인됐습니다. 이 사실을 유지한 상태에서 사용자가 v7.4의 bank를 S5로 선택했고, 실행 전에 고정했습니다.
- 조립체별 SKILL.md는 각 CAD의 1차 반복 1회차 A·B·C 기록으로 작성됐습니다. 2차 시도는 같은 조립체의 경험을 재사용하는 평가이며 새로운 CAD에 대한 일반화 평가로 세지 않습니다.
- 36회에는 같은 CAD의 반복이 포함됩니다. 서로 다른 CAD 36종이나 180종에 대한 검증으로 해석하지 않습니다. 선정에는 기존 형상·초기 물리·P2 참조 경로 기준을 적용했으며, 참조 경로는 planner에게 제공하지 않았습니다.
- 부품 10개 이상에 대한 성능은 이 실험으로 판단할 수 없습니다.
- 조건별 해석과 한계는 [EVALUATION_RESULTS.md](EVALUATION_RESULTS.md)에 있습니다.

## 검증 상태

**2026-11-18 독립 재생 검증: 180/180 PASS.**

- 모델을 호출하지 않고, 기록된 API event를 실제 simulator(E1 포함)로 순서대로 다시 실행했습니다. event마다 trace 항목, 상태 key, 청구된 검사 수가 같은지 확인했습니다.
- 물리 검사 2,081회를 다시 실행했고, 저장된 청구 검사 2,081회와 같았습니다. 조건별로 36/36 PASS였습니다.
- 실행 시간은 43분 52초(worker 6개)였고, 토큰은 쓰지 않았습니다.
- 재생 뒤에도 고정 파일 21개의 해시가 기존 amendment 기준으로 일치했습니다.
- 재생 검증은 저장된 물리 판정과 검사 비용의 재현을 확인합니다. LLM 응답을 다시 생성하지 않으므로, 모델 행동의 재현성을 뜻하지 않습니다.

2026-11-10 공개 준비에서 확인한 것은 다음과 같습니다.

- 저장된 180개 에피소드의 성공 여부를 원본 결과·지표와 대조했습니다.
- 실행별 CSV의 검사 수, 실패 검사 수, 필요 제거 수, 호출 수, 토큰 수를 저장 지표와 대조했습니다.
- 기존 amendment를 반영한 고정 파일 21개의 해시가 일치했습니다.
- 고정 기록이 지정한 planner 모듈 13개가 v7.3과 바이트 단위로 같았습니다.

## 포함한 파일

- [`../../disassembly_repair_v7_4/`](../../disassembly_repair_v7_4/): 기존 코드·상태·계획. 실행 당시 원본을 보존하고 로컬 절대경로만 치환했습니다. STATUS.md에는 2026-11-18 항목이 추가됐습니다.
- [`EVALUATION_RESULTS.md`](EVALUATION_RESULTS.md): 평가 보고서(2026-11-18). 보고서의 원자료 경로(`outputs/...`, `analysis/...`)는 원본 작업 공간 기준입니다. 공개된 파일은 이 목록에 있습니다.
- [`RESULT_TABLES.md`](RESULT_TABLES.md), [`evaluation_runs.csv`](evaluation_runs.csv), [`summary_v74.json`](summary_v74.json): 집계. 2026-11-18 재실행에서 실행별 CSV는 바이트 단위로 같았고, 집계 JSON은 `utc`와 `replay`만 바뀌었습니다. 2026-11-10 공개본에서만 고쳤던 결과표의 Markdown 구분선은 재실행한 원본에서도 바르게 출력되므로, 이제 공개본과 원본 결과표가 같습니다.
- [`records/replay_audit/evaluation.json`](records/replay_audit/evaluation.json): 180회의 에피소드별 재생 판정과 재생한 물리 검사 수.
- [`memory/`](memory/): 범용·조립체별 SKILL.md와 bank manifest.
- [`records/protocol/`](records/protocol/): 후보 순서, 선정 결과, 고정 기록, amendment.
- [`records/evaluation/`](records/evaluation/): 완료 표시와 180회 실행별 요약 지표.
- [`records/note_writer/`](records/note_writer/): 조립체별 SKILL.md 작성 요약과 사용량. Provider 원문은 포함하지 않습니다.

원본 CAD, 변환 case·mesh, raw episode 결과·trace, provider 프롬프트·응답·호출 로그, 재생 실행 로그, 환경·인증 정보는 포함하지 않습니다. 기존 `disassembly_repair_v7.publish`의 allowlist 복사·크기 제한·secret 검사·경로 치환 함수를 사용했습니다.

이 저장소는 코드와 요약 근거의 공개 스냅샷입니다. 원래 작업 공간의 데이터·출력·SKILL.md 경로를 보존한 코드이므로, 저장소만 clone해서 원본 평가나 재생 검증을 바로 재실행할 수 있다는 뜻은 아닙니다. 고정 기록의 해시는 원본 파일 기준이며 경로 치환된 공개 사본의 해시와 다를 수 있습니다.
