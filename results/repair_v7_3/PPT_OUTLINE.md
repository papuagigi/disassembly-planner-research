## S5 기준으로 보여 주는 이유와 공개 사항
- S5는 v7.3에서 새로 만든 최신 범용 SKILL.md입니다. S3는 v6에서 만든 이전 버전 2개입니다.
- S5는 개발 검증에서 불승인됐습니다(A 8/8, B·S5 6/8, C·S5 8/8). 실행 전에 정한 규칙상 평가의 주 분석은 S3입니다.
- 발표는 최신 버전인 S5를 기준으로 보여 주되, S3 결과를 같은 표에 회색 행으로 두고, 불승인 사실과 주 분석이 S3라는 점을 8장(실험 환경)과 11장(개발 검증)에 적었습니다.
- 성공 수는 두 버전이 같습니다(1차 B 3/4, C 4/4). 그래서 S5 기준으로 보여 줘도 성공에 관한 주장은 달라지지 않습니다.

## 슬라이드 구성
1. **표지**
2. **연구 동기 · 선행 연구가 남긴 질문**
   - ASAP §VI 실패 사례: 끝까지 탐색해도 해 없음 50%, 접촉이 복잡해 물리 평가가 느림 45%, 엄격한 선후 제약으로 예산 내 실패 5%.
   - ASPIRE §5 한계: frontier LLM(Claude Opus 4.6)에 의존, 더 작거나 약한 LLM에서는 검증하지 않음. 라이브러리 항목이 오래되거나 지나치게 구체적이 될 수 있음. 호출·시뮬레이션 비용이 큼.
   - 연구 질문: 성능이 약한 LLM에서도 분해 실패에서 배운 절차를 SKILL.md로 남기면 분해 계획이 나아질까?
3. **연구 목표와 용어:** SKILL.md / 범용 SKILL.md(처음 보는 조립체용, S5 기준·S3 비교) / 조립체별 SKILL.md(같은 조립체용).
4. **Disassembly planner란:** 입력 CAD → 행동(부품, 방향 라벨) → 경로 충돌 판정 → MuJoCo 잔여 안정성 판정. 성공 조건, 어려운 이유, 검사 비용(충돌 거절 중앙값 2.1초, 불안정 판정 19.6초).
5. **A·B·C 구조와 도입 이유**
   - A: LLM이 탐색 코드를 직접 작성, SKILL.md 없음(기준선).
   - B: 같은 방식에 SKILL.md를 먼저 읽고 코드에 반영.
   - C: LLM은 후보 순위만, 탐색은 고정 DFS. SKILL.md는 순위 판단에 참고.
   - A↔B는 SKILL.md의 효과, B↔C는 역할 분담의 효과. 같은 모델·API·예산.
6. **범용 SKILL.md(S5)를 만드는 방법:** 개발 CAD 5개의 모든 질의를 실제 방향 기준으로 집계 → gpt-6-luna가 근거를 인용해 작성 → 참조 코드를 모델 없이 실제 물리로 실행(5개 중 4개 완전 분해). 근거와 규칙의 대응표, 실제 파일 발췌(`memory/S5/world-family-disassembly-search/SKILL.md`).
7. **조립체별 SKILL.md를 만드는 방법:** 1차 시도 기록 3개 → 모델이 설명 작성 → host가 가장 완전한 경로를 그대로 첨부 → 2차에서 기록된 순서를 먼저 시도. 실제 파일 발췌(03937, S5 분기: 1차 중 검사가 가장 적었던 B·S5의 19회 경로).
8. **실험 환경과 평가 설계:** 모델·예산·개발/평가 CAD·절차 표, CAD마다 1차 5회 → 조립체별 SKILL.md 2개 → 2차 9회(총 56 에피소드), S5 불승인과 주 분석 S3 공개.
9. **결과 ① 같은 조립체:** S5 분기 1차 → 2차 표.

   - 조립체별 SKILL.md 없는 2차 시도 9/12.
10. **결과 ② 처음 보는 조립체(1차)**
    - A 3/4, B·S5 3/4, C·S5 4/4.
    - S3(회색): B 3/4, C 4/4. 성공 수는 같고 검사 수는 CAD마다 엇갈림.

11. **결과 ③ S5 개발 검증:** 조건별 하는 일, 성공, 검사 수 중앙값(성공 에피소드만) 표, 승인 규칙. 03674 사례: 부품 0을 옆으로 먼저 빼야 하는데 B·S5가 위 방향 부품부터 빼서 가둠, 같은 제거·복원 반복으로 예산 소진.
12. **시사점**
    1. 조립체별 SKILL.md는 바로 효과가 있음.
    2. 범용 SKILL.md는 가정을 확인하는 조건부 형태가 필요.
