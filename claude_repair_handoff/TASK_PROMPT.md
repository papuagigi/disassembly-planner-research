# Claude Code에 입력할 문제 해결 프롬프트

이 문서는 사용자가 Claude Code에 직접 입력할 작업 지시다. 문서 작성만으로 Claude가 실행된 것은 아니다. 기존 v6 중단 복구 프롬프트와 구분한다.

---

이 disassembly planner 프로젝트의 현재 문제를 실제 로그와 코드로 확인하고, **기존 결과를 보존한 새 버전에서 해결**해줘. 단순히 B나 C가 A보다 높게 나오게 만드는 것이 목적은 아니야. 목표는 **실제 분해 실패에서 배운 절차를 SKILL.md에 저장하고, 처음 보는 조립체를 분해할 때 이 경험이 도움이 되는 시스템**이야.

작업 폴더는 `/Users/juyeonkim/Documents/경희대학교 26-2학기 관련 문서/독립심화학습`이야. 먼저 루트 `CLAUDE.md`, `claude_repair_handoff/README.md`, `FAILURE_DIAGNOSIS.md`, `evidence.json`을 읽어줘. 뒤의 세 파일은 `claude_repair_handoff/` 안에 있어. 분석 문서의 주장도 원본 로그로 확인하고, 동의하지 않는 부분은 근거를 제시해줘.

`disassembly_final_v6`의 3 CAD × A·B·C = 9회 평가는 이미 완료됐어. 모두 완전 분해에 실패했고, 새 skill 후보도 검증에서 기각되어 기존 문서 2개를 사용했어. 이 평가를 재개하거나 수정하지 말고 새 디렉터리와 별도 결과 경로를 사용해. 05954·06444·03114는 이제 원인 분석·회귀 검증에만 쓰고, 다음 평가에서 ‘처음 보는 제품’으로 다시 세지 마.

우선 확인할 문제는 세 가지야. A는 05954에서 이미 소진한 성공 분기로 59번 재진입했어. B는 같은 CAD에서 탐색을 재개하지 못하고 추가 검사 없이 LLM 호출을 6번 반복했어. C는 06444에서 실제로 가능한 첫 행동을 계속 뒤로 미뤘고, 깊은 탐색 전에 순위 결정 호출을 다 썼어. 이를 오프라인 회귀 검증으로 재현한 뒤, 탐색 상태 보존·분기 소진 기록·무진행 호출 처리·후보 순위와 호출 시점을 최소한으로 개선해줘. 수정 방법은 코드를 보고 결정하되 A/B에 고정 DFS를 몰래 넣어 원래 조건의 의미를 바꾸면 안 돼.

물리 모델도 별도로 확인해줘. 현재는 한 부품 영구 고정, 회전 없는 6방향 직선 이동, 별도 OBJ 충돌 검사, MuJoCo 잔여 안정성 검사야. 초기 안정성 통과가 완전 분해 가능성을 증명하지는 않아. 개발 사례에서 같은 검사기/API로 완전 분해 경로를 검증하고, 충돌 형상·실제 이동 벡터·고정 조건·허용 동작 중 무엇이 제약인지 구분해줘. 성공을 만들기 위해 임의로 충돌 판정을 약하게 바꾸지 말고, 변경이 필요하면 이유와 비교 조건을 기록해.

A는 LLM 코드 생성·외부 library 없음, B는 LLM 코드 생성·SKILL.md 있음, C는 조건부 Graph·LLM 순위·DFS·같은 SKILL.md라는 역할을 유지해. 소프트웨어 오류 수정과 실제 분해 실패에서 배운 skill을 구분해줘. 새 skill은 개발 실패 로그로 만들고 별도 검증 후에만 채택해. B·C는 동일하게 고정한 문서를 사용하고, 평가 중에는 갱신하지 마.

먼저 작은 회귀 검증을 끝내고, 새로운 CAD의 소규모 첫 실행 평가 범위와 선정 규칙을 결과를 보기 전에 정해줘. 세 조건 모두 기본값인 **gpt-6-luna low, 4GiB, LLM 8회, 물리 검사 240회, 900초, 같은 상태 복원 API**를 유지하고 planner는 하나씩 실행해. 상세 상한은 인계 문서와 기존 freeze 기록을 따라줘. Claude는 코드를 고치는 담당자이고 평가 LLM을 Claude로 바꾸는 뜻은 아니야. 동일 모델 호출이 막히면 가능한 코드·오프라인 검증은 진행하고 미실행 평가와 원인을 기록해줘. 큰 추가 실험이나 모델 변경은 별도로 제안해.

성공률뿐 아니라 최종/최대 제거 수, 첫 유효 행동까지의 검사 수, 분기 재방문, 실패 시도, 복원, 무진행 LLM 호출, 실제 시간·토큰을 남겨줘. 물리 불가 판정, 시간/검사 예산 종료, MuJoCo 자원 부족, provider 오류, 탐색 오류를 구분해. 새 결과는 실제 MuJoCo 다시보기와 agent용 MD·JSON·CSV로 정리해줘. 기존 테스트 로그를 참고해 고쳤다면 같은 CAD의 재실행을 새 제품 첫 시도 성능으로 보고하지 마.

처음 답변에서는 확인한 현재 상태와 구체적인 수정·검증 순서를 짧게 알려주고 진행해줘. 중요한 단계마다 새 버전 `STATUS.md`에 상태와 다음 작업을 기록해. 특정 조건이 이길 때까지 반복하지 말고, 검증한 사실과 남은 한계를 함께 보고해줘. **PPT는 아직 만들지 마.**
